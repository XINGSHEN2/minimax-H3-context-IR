# H3 内容大纲规划

本 Skill 只决定“发生什么”。调用方提供原始用户要求、解析结果、素材证据、创作权限和目标时长。输出并锁定 `creative_brief`、`requirement_map`、素材 `bindings` 与 `developments`；镜头数量、景别、机位、运镜、切点、转场和声音由后续 Skill 决定。

## 权威与证据

原始 `user_request` 具有最高任务权威；`resolved_request`、`directives` 和 `completion_policy` 只帮助解释，不能增加用户没有表达的限制。用户只描述某个 Shot 时，默认只约束该片段；只有明确要求“仅一个镜头”“一镜到底”“不得增加镜头”、完整锁定分镜或严格迁移时，才限制开放部分。

区分用户要求、素材可见事实和创作补全。带“可能”等限定的观察不是确定事实；重复描述不是独立证据。身份图、场景板、风格参考、动作阶段图和时间故事板用途不同。图片数量、素材区域和感知分段都不决定 development 数量。

人物和产品只保留足以维持身份、核心轮廓、交互和用户指定用途的高价值锚点。用户点名的属性必须保留；未点名细节只有在缺失会改变身份、核心外观或动作关系时才进入最终 H3。静态姿态不证明动作、时序或隐藏机制。

## 要求分层

先建立 `requirement_map`：

- `content_events`：故事世界中人物、物体、关系、信息或空间的动作与结果；
- `editing_treatments`：剪辑、转场、闪白、黑场、故障、残影、文字动画等表现；
- `global_style`：媒介、类型、色彩、摄影和贯穿质感；
- `audio_requirements`：音乐、环境声、同步声、静音、对白、歌词和音轨复用。

分类不能删除要求。未标为片尾的 hard cut 要有切入内容，但 hard cut 自身不是内容事件。

## Development 的语义单位

一个 development 表示完成后会改变后续条件的叙事状态变化。它必须带来可见的动作、关系、空间、故事内信息、物品归属或结果变化，并记录稳定 `id`、`source_content_event_ids`、`visible_change` 与 `outcome`。

Development 不表示观察角度、景别、拍摄阶段或效果阶段。以下内容本身不能形成 development：

- 外景、内景、广角、特写、反应镜头或新的观看位置；
- 变亮、变响、变震、强度增强或同一现象的不同程度；
- 标题出现、字距变化、扫光、残影、闪白、黑场、故障和声音标点；
- 为覆盖服装、材质或产品细节而改变观察方式。

当触发、执行、即时反应和直接结果共同完成同一目标时，将它们组成一个 development。不同空间中的观察与反应，如果只是同一核心事件的互补呈现，仍属于同一个 development；由分镜阶段决定是否需要多个视点。

只有出现新的独立目标、不可逆状态、主体关系变化、物品归属变化、时空跳转或用户明确锁定的独立事件时，才建立新的 development。

## v33 核心压缩原则

1. **连续目标合并**：开箱、取出、提起并让物品落到手边，若共同完成“取得物品”，默认是一条 development；启动、加速、达到跃迁并产生直接冲击，若共同完成一次跃迁，也默认是一条过程。
2. **表现层剥离**：去掉标题、闪白、黑场、声音、机位和转场后，没有独立状态变化的条目必须降为 treatment 或删除。
3. **视点剥离**：去掉“外景、舰桥、近景、反应”等观看位置后，两条内容仍是同一核心事件的不同观察，就合并。
4. **强度剥离**：轻微、增强、峰值和消退若只是同一现象的连续强度变化，不拆分；只有峰值触发了新的不可逆结果时才分开。
5. **删除检查**：删除新增事件后用户目标仍完整，则删除该事件；不要为“更宏大、更电影化”添加支线、重复高潮、恢复起始构图或第二种结局。

文字或版式只有在它本身是用户要求的主要生成内容时，才可作为整体 development。同一语义组中的主标题、副标题、说明行和品牌落款默认保持为一个不可拆文字组，除非用户明确要求分时或分卡展示。

## 主体、顺序与状态

保留核心事件的实际执行主体、群体范围、动作类型、先后关系和用户要求的结果。群体执行不能缩成单个主体执行；观察者反应不能替代执行者行动。初始位置用于识别主体，不自动锁定其全程位置。

“依次、然后、最后”和“同时”保持各自含义。多主体换位、交接、取得、穿戴、启用或损坏时，追踪稳定主体 ID、位置、持有关系和可见状态。完成态参考不能让后续才取得的物体提前出现。

大纲必须单向推进。后一个 development 继承已经到达的状态，不能重新启动已完成动作、回到旧状态、重复同一高潮或让离开的主体无依据返回。

## 创作权限

默认采用“完成用户意图所需的最小充分补全”。开放设计允许补足动作连接、可辨识结果和必要表演，不等于允许扩写故事。新增事件必须填补因果缺口、完成指定展示或使明确结果成立。

只有用户明确要求自由创作完整故事、多段表演或剧情转折时，才建立多条新增动作弧。时装、造型和产品展示优先围绕一段有方向的连续表演组织，不为每种展示维度重新启动动作。

## 锁定检查

锁定前依次执行：

1. 删除镜头、角度、标题、特效和声音词语，确认每条仍有独立状态变化；
2. 检查同一核心事件是否因不同视点或强度被重复拆分；
3. 检查执行主体、群体范围、动作顺序、物品状态和最终结果；
4. 检查每个非用户明示事件是否确实连接两个必要状态；
5. 确认 developments 单向、最小且充分。

锁定后交给 H3 Shot Planning Skill。下游只能决定怎样拍，不能新增、删除、合并、拆分、替换或改写 developments；若发现语义冲突，返回本阶段修正。
