# H3 分镜规划

输入是用户要求、素材用途、已确定的 `developments` 和目标时长。输出按播放顺序排列的 `shots`，以及 `h3_prompt.detailed_description` 中可直接用于 H3 的英文 `[Shot N]` 正文。遵守 H3 Prompt Writing Skill 的参考标签和语言格式。本阶段只决定怎样拍已确定的内容，不增加、删除或改写事件；大纲若有矛盾，退回 Outline Planning Skill 修正。

## 第一步：确定每段要看见什么

按发生顺序读每条 development 和用户明确要求。先确定观众要看见的起始状态、动作或展示过程、直接结果，以及必须读清的文字、材质、人物反应或参考构图。每个要求都要有落点；没有画面依据的细节不要编成素材事实。

## 第二步：决定哪里切镜

先读取每条 development 的 `estimated_duration_seconds`，据此安排主要内容的时间，再决定切镜和展开镜头细节。这是事件的预计时长，不是镜头切点；一个 development 可以跨镜，连续的多个 development 也可以同镜。可按动作和观看需要调整分配，但不能把主要动作挤在短时间内，再靠重复状态或收尾填满剩余时间；最终镜头时间须连续覆盖目标时长。

同一时间、地点、主体和动作目标，先用一个连续镜头安排准备、动作、必要细节、即时反应和结果。一个 Shot 可以随人物运动改变构图、景别或焦点，不必始终停在同一机位和景别。

只有以下情况才增加 Shot：时间或地点改变；主要观察对象或人物之间的关系真正改变；当前镜头即使跟随主体、移动摄影机、重新构图、改变景别或焦点，仍无法看清用户要求的内容或重要结果；用户或参考明确指定切点或独立片段。用户明确要求蒙太奇、舞蹈卡点或独立产品展示时，按指定的剪辑结构安排镜头。快节奏、硬切和电影感只决定必要切点怎样表现，不自动增加镜头。标题变化、闪白、黑场、故障、震动和普通反应附在它们表现的动作或已有切点上，不因效果出现就单独成镜，除非用户或参考明确要求独立片段。

同一版式组的主标题和副标题默认放在同一个 Shot 中。只有用户明确要求分别成镜或使用独立标题卡时，才拆成不同 Shot。

列出初步镜头后，逐个检查切点：删掉它，动作能否自然连续？后镜要看的哪项必要内容，是前镜通过主体或摄影机运动、重新构图、改变景别或焦点仍拍不清的？这个切点是否由用户、参考、真实时空变化或观察对象变化指定？如果删掉能自然连接，且后两问都没有具体答案，就合并。只多一个角度、再次展示同一标题材质或把同一次震动拆成几个景别，不是充分理由。镜头数由内容决定，不设固定数量。

## 第三步：直接写每个镜头

每个 [Shot N] 正文先写清摄影机从哪里、朝哪里看，主要看见谁或什么，它们在哪里、处于什么状态，以及与周围环境的位置关系。随后按发生顺序写动作和变化：谁怎样行动，物体怎样移动或改变，动作怎样影响其他主体、光线和环境。最后写清镜头结束时留下的画面和状态。不必逐项罗列前景、中景和背景，但要让人读懂同一画面中的空间关系。不要只写“展示产品”“人物反应”或一个景别名称，让后续步骤猜内容。

把本镜必须看清的细节写在对应动作中：人物与物体的具体特征，以及用户要求的材质、结构、文字或表情，在什么时候、什么画面和光线下看清。固定外观和场景可以引用已定义的 Subject、Picture 或 Video，不逐镜重抄，但不能省略本镜实际要展示的细节。针对参考素材的画面修改，要在出现该内容的镜头中明确写出原来是什么、改成什么。对白、旁白和歌词替换是例外：Shot 只写最终要发声的内容，不提被替换的旧台词；新旧对应关系留在前面的修改说明中。

参与动作的物品，要先交代动作开始前它在哪里、由谁持有或处于什么状态，再写怎样改变。只描述与本镜动作或后续镜头有关的主体，不逐一罗列背景物。内容须符合用户目标和素材依据，不把补全当成素材事实，也不为填满时间增加动作或物体。

一个 Shot 只容纳同一连续时空中的动作。摄影机使用一条连贯路径，写清怎样跟随动作或重新构图；没有观看作用时保持稳定，不能同时要求固定机位和移动摄影机。摄影机变化应穿插在对应画面和动作中，让观看位置始终清楚。

参考图作为镜头起点时，首次清晰画面须符合其主体位置、姿态、持物状态和构图；作为目标时，写清怎样通过连续的动作或摄影机运动到达它。到达后不重复呈现同一关键帧，也不擅自增加人物重新入画或寻找目标的过程。

与画面精确同步的对白、动作声和转场声，直接写在触发它们的动作旁，自然穿插，不在镜头末尾另列声音清单，也不为每次切镜添加音效。持续环境声和画外配乐留给 Sound Planning Skill。

## 第四步：连接镜头并分配时间

第一个镜头 `[Shot 1]` 不写时间；从 `[Shot 2]` 起，只在编号后写该镜的切点时间。镜内动作和转场用“随后”“镜头末尾”等顺序描述，不再写第二个时码。

逐对检查相邻镜头，确保镜头之间逻辑性合理：前镜结束时，人物在哪里、动作做到哪一步，关键物品在哪里、由谁持有，物品处于什么状态；后镜从这些状态继续。没有拍到改变状态的动作，就保持原状态；即使物品暂时离开画面，它再次出现时也必须接上此前状态。若两镜之间确实需要拿取、放下、开关或交接，应把动作安排在其中一镜，不让变化凭空发生。服装、运动方向、环境和需要延续的声音同样接上。

每个切点写清前镜从什么画面离开、怎样切换，以及后镜第一帧看见什么。硬切直接到新画面；甩镜写清甩动方向和落到的对象；闪白、黑场、遮挡或故障只在边界的一侧执行一次。除非用户或参考要求返回或闪回，换到新画面后旧画面不重新清晰。转场不能凭空增加动作或延长事件。

## 输出与检查

每个 `shots` 条目写 `id`、`development_ids`、`content_purpose`、`treatment_ids`、`start_seconds` 和 `end_seconds`。完整镜头文字只写在 `h3_prompt.detailed_description`，每镜以独占行首的 `[Shot N]` 开始，编号与 `shots` 一一对应；不再输出另一套镜头正文。提交前检查：除镜头开头的切点时间外，各镜正文不得再出现具体时码。

提交前检查：用户要求和 developments 是否都拍到了；相邻两个镜头是否确实需要分开，能连续看清就合并；同一组主标题和副标题是否被拆成多个分镜，除非用户明确要求分别成镜或独立标题卡，否则合并到同一镜头；每镜的画面、动作和摄影机是否具体可拍；逐镜核对关键人物与物品的起始状态、可见变化、结束状态和下一镜起点，找不到执行动作的状态变化必须修正，同时检查关键帧、声音和转场是否接得上。锁定后交给 Sound Planning Skill；后续只排版，不重新设计镜头。

对白标签边界：<d> 只表示目标视频中实际发出的对白或歌词，仅写在 detailed_description 对应的发声位置。待替换、删除或仅用于解释的原句使用普通引号，不能放入 <d>。subject_definitions、summary、retention_analysis 中的新旧对白均用普通引号说明；对白、旁白或歌词被替换时，相关 Shot 只写最终实际发声内容并使用 <d>；不得在镜头正文中引用、复述或用否定句提及被替换的旧台词，即使用普通引号也不允许。新旧台词对应关系只留在前面的修改说明中。保留不变且实际发出的原对白仍可使用 <d>。招牌、字幕等可见文字继续用普通双引号写清原文和目标文字，不使用 <d>，也不因此省略替换关系。
