# 内容优先的 IR 简化实验

更新：2026-09-07。

## 目标与边界

优先保证用户要求、素材来源、主体辨识特征、动作状态和声音内容。轻微格式差异不应反复调用模型。是否达到官方效果水平，最终需根据内容覆盖和生成视频对照判断，不能用格式通过率或长度替代。

## 已部署行为

`backend/context_ir.py` 的最终 Prompt 合约检查将下列差异记录为 warning，不因此触发模型重写：章节顺序、额外标题、行内镜头引用、summary 任务前缀及开头句式。

缺失必要正文、引用不存在的素材、时间越界等检查仍保留。诊断记录仍输出给调用方。相关 132 项测试通过；这不代表模型语义质量已验证。

`backend/agent.py` 要求最终表达保留 IR 已有的音效与同步事件，减少定义、保留说明及逐镜之间的重复清单。Case 1 复测恢复了此前遗漏的对焦、甩镜、布料及脚步声。

## 实验入口

可复用后端函数已独立为 `backend.compact_writer.write_compact_prompt(evidence, invoke)`。调用方准备规范化证据，注入带 H3 Skills、模型选择和日志的调用函数。模块在一次正常调用中返回 content_plan 和 Prompt，保留原样文本，不声称生成了旧版 canonical IR。测试验证调用方约束不被删除、输入不被修改、缺失计划或正文不返回成功。

`scripts/retest_realization.py BASELINE OUTPUT --direct-evidence` 使用原始需求、已有 `media_analysis.json` 和 H3 Skills，调用一次 DeepSeek 官方模型生成 Prompt。已有 Qwen 分析必须非空。该分支不重新解析意图，也不重新运行 Qwen。

最新实验要求在同一返回对象内先提供简短 `content_plan`，再提供 `h3_prompt`：

- `must_keep`：用户要求及主体辨识细节。
- `task_mode`：生成、参考迁移、局部编辑或续写；与服务层 ref2va 类型分开。
- `bindings`：素材 ID、角色、保留属性、排除属性。
- `shots`：起止时间、起始状态、动作、结束状态和声音事件。

这是供测试和追踪使用的简短生产记录，不是推理过程。没有新增独立审核调用。该分支尚未接入公开 API，也没有生成旧版完整 canonical Context-IR；不得将它伪装成旧版 `context_ir`，或声称已有接口协议完全兼容。

## 已观察到的结果

均为同一已部署 Qwen 的历史分析、DeepSeek 官方 `deepseek-v4-flash`、high 推理强度；未生成本轮视频。

| 案例与实验 | 耗时 | 字符数 | 内容观察 |
|---|---:|---:|---|
| Case 1 直接生成 | 231.212 秒 | 8,215 | 固定遮罩、四图顺序、动作和声音基本保留，仍有重复与 OCR 文本风险 |
| Case 4 初次直接生成 | 169.028 秒 | 5,845 | 故事与持包状态保留，但将圆形加竖杆扣件写成泛称，且推断锁扣位置 |
| Case 4 加入辨识细节规则 | 207.593 秒 | 6,960 | 圆形加竖杆扣件恢复，未再指定不明锁扣位置 |
| Case 3 直接生成 | 183.557 秒 | 4,651 | 开场要求保留，但新增人物消失，且门口状态在镜头之间回退 |

由此增加简短内容与镜头状态记录的同调用实验，检查能否改善多镜连续性和补全尺度。上述耗时仅包含证据之后的调用，与包含 Qwen 的全新素材流程不可直接比较。

同调用记录的后续结果：

- Case 3：149.304 秒，4,052 字符，缩为两镜。人物从原地走近门口后停下，避免了上一版的重复到达与消失；标题、开场位置、低频脉冲和标题清晰时的 hit 保留。
- Case 5：171.098 秒，6,529 字符，主要服装特征、火光反射、故障效果和声音覆盖保留。但氛围参考中的车辆被继承，且逐镜描述与音乐段落对 14.8 秒的结束状态不一致。因此仍不能判定为稳定可替换的生产方案。

针对 Case 5，同一调用内的 `excluded_attributes` 与唯一音频结束 cue 已完成一次验证：`feishu_case5_direct_scope_20260907` 用时 179.071 秒，5,388 字符、五镜。结果明确排除车辆和原图字样，保留人物服装、火光反射与故障效果；环境声和音乐均在 14–15 秒淡出。前版的两项问题已在这次输出修正，未增加独立审核环节。仍需要跨案例与实际视频验证，不能把单次成功视为稳定保证。

## 替换生产路径前必须验证

1. 不丢人物、商品和可辨识属性；不混淆各素材的作用。
2. 已指定内容不被补全改写；新镜头承接已有状态，不擅自增加消失、破坏等剧情结果。
3. 声音、对白、静音和同步要求完整，声源事实与设计音效分清。
4. 对图片、多图、视频参考、局部编辑等不同输入分别验证。
5. 保留公开 API 输出协议；若采用新的轻量 IR，明确版本及兼容策略。
6. 用相同生成参数对比官方和本地 Prompt 的实际视频及音频。

当前尚无证据证明整体已达到官方水平的 80%，不应直接全量切换。

## 视频参考与音频状态修复

新增复测不分析音频内容，使用已有 Qwen 视频证据与用户明确提供的中文台词。

- 动作迁移首次直写：131.854 秒，动作大致齐全但自行拆为四镜。加入任务模式边界后：156.725 秒，恢复一镜，保留左右站位、递盘、右手甩泡沫、反击、互泼闪躲和大笑。末尾仍自行减速收尾，严格表演节奏未完全验证。
- 台词替换首次：126.690 秒；加入模式边界后：93.081 秒。台词完整，但仍存在把局部编辑写成参考重生成、凭未分析音频禁止复用、编造背景声细节的问题。

排查发现 `backend/perception.py` 会把视觉提供方跳过的空音频条目从 unsupported_by_visual_provider 改成 invalid_placeholder。已改为 not_analyzed，并修复相同类型的旧缓存条目；不生成转录、时长或音色事实，也不据此保证音频文件可访问。真正空白的视频分析仍判无效，外部已有音频证据仍保留。60 项相关测试通过；修复后的真实模型复测另外记录。

修复后的 `feishu_dialogue_audio_status_20260907` 用时 159.805 秒，2,763 字符。实际输入的音频状态为 not_analyzed；输出采用 video editing + audio reference，保留新台词、原镜头和光线，以及未替换的非对白音频，不新增未分析的环境音细节。它选择复用台词内容而非音频波形，符合本例“改成音频的台词”的一种解释；若调用者明确要求直接用原音轨，还需单独验证该要求不会被改成重新配音。

模块化之后实验入口也保留原始 input 中已有的 directives 和 completion_policy，避免测试脚本人为移除调用方约束。本例是在该入口上实际运行，不能把此前省略这些字段的实验当成完全相同的输入。
